# Engine source patches

The QuickJS-NG engine source under `vendor/quickjs/source_ng` is a git submodule
pinned to an upstream commit. Our hand-written NativeScript changes are kept here
as a patch applied on top of that pristine checkout, rather than baked into a
vendored copy.

```
tools/patches/
  quickjs_ng/  0001-nativescript-local-changes.patch   (quickjs-ng/quickjs)
```

QuickJS-NG is the only QuickJS lane left: the bellard tree was dropped, and
`QUICKJS` is an alias for `QUICKJS_NG` (see `test-app/runtime/build.gradle`).

The patch touches nine files. Most of the change is in `quickjs.c` / `quickjs.h`
-- the `USE_HOST_OBJECT` host-object hooks in `JS_GetPropertyInternal` (host
objects act as a non-masking prototype fallback) and the functions after the
`/* CUSTOM */` marker -- plus tvOS/watchOS support in `CMakeLists.txt`,
`meson.build` and `quickjs-libc.c`, and a few upstream fixes backported ahead of
the pin (`cutils.h`, `dtoa.c`, `dtoa.h`, `libregexp.c`).

## Managing them

The patch is generated by diffing the working tree against the pinned commit:

```
git -C vendor/quickjs/source_ng diff > platforms/android/tools/patches/quickjs_ng/0001-nativescript-local-changes.patch
```

Because the submodule work tree is patched in place it is always dirty, which is
expected -- `.gitmodules` sets `ignore = dirty` so `git status` stays quiet. Edit
the engine by editing that work tree, then regenerate the patch with the command
above.

On a fresh checkout / in CI:

```
node platforms/android/scripts/setup.js
```

which runs `git submodule update --init --force`, hard-resets the submodule to
the pinned commit, and re-applies the patch. It is idempotent.

## Compatibility

The submodule commit sets the engine's `BC_VERSION`. The compile-time bytecode
CLI (see `.github/workflows/bytecode-compilers.yml`) MUST be built from the same
commit, or `JS_ReadObject` rejects the produced bytecode at runtime and the app
dies on launch with `SyntaxError: invalid version (N expected=M)`. Keep the
workflow ref and the submodule pin in lock-step.

Current pin: `6a9fe9af5ca0bf7c49ae697edef44864272317d1` (v0.11.0, `BC_VERSION 21`).
